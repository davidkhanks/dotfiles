# YubiKey SSH

SSH authentication is backed by a YubiKey. The private key never leaves the
token.

| | |
|---|---|
| Device | YubiKey 5C NFC, firmware 5.7.4 |
| Key location | **PIV slot 9A (AUTHENTICATION)**, ECCP256, `CN=davidhanks-yubikey` |
| Public key | `~/.ssh/id_yubikey_piv.pub` (regenerated by `bootstrap.sh`) |
| Fingerprint | `SHA256:G9Ql17dnVcM5Bk/JFXzVSzZVlZgg4aM9HTQcqeeuY1I` |
| Reached via | PKCS#11, `/usr/lib/libykcs11.so` (from `yubico-piv-tool`) |

## The key is PIV, not FIDO2

This matters more than it sounds. A YubiKey holds **three independent PINs**:

| PIN | Used by | Attempts |
|---|---|---|
| **PIV** | this SSH setup, `libykcs11` | **3** |
| FIDO2 | `ssh-keygen -K`, WebAuthn | 8 |
| OpenPGP | GPG smartcard | 3 |

`ssh-keygen -K` asks for the **FIDO2** PIN and will not find this key — it
downloads *resident FIDO2* credentials, which is a different mechanism
entirely. Feeding it the PIV PIN just burns a FIDO2 attempt and fails with a
misleading message:

```
Provider "internal" returned failure -3
Unable to load resident keys: incorrect passphrase supplied to decrypt private key
```

`-3` is OpenSSH's `SSH_SK_ERR_PIN_REQUIRED`; the "incorrect passphrase" line is
OpenSSH mis-mapping it. Nothing is corrupt.

**Lockout consequences differ:**

- **PIV PIN**: 3 attempts, then the PUK unblocks it (3 more). Exhausting both
  forces a PIV reset, which **destroys the slot 9A key**.
- **FIDO2 PIN**: 8 attempts, then the applet locks and only a reset recovers it
  — **destroying every resident credential**, which cannot be backed up.

Do not guess at either. There is one FIDO2 resident credential on this key
(unrelated to SSH, probably a website WebAuthn login) and no backup of it.

The OpenPGP applet is empty; this is not a GPG-based setup.

## What `bootstrap.sh` sets up

1. Installs `libfido2`, `yubikey-manager`, `yubico-piv-tool`, `pcsclite`.
2. Enables **and** starts `pcscd.socket`.
3. Exports the slot 9A public key to `~/.ssh/id_yubikey_piv.pub` (no PIN needed
   — public keys are freely readable).
4. Verifies OpenSSH can see the key through PKCS#11.

`~/.ssh/config` comes from the `ssh` stow package, not from the script, so edits
stay version-controlled.

### Two things that bite on a fresh Omarchy install

**`libfido2` may be absent.** `ssh-sk-helper` then reports
`libfido2.so.1 => not found` and OpenSSH cannot talk to *any* hardware key.
Check with `ldd /usr/lib/ssh/ssh-sk-helper | grep fido`.

**`pcscd` must be *enabled*, not merely active.** PIV/CCID access goes through
PC/SC. A running-but-disabled socket works until the next reboot and then
silently stops. `bootstrap.sh` checks both states separately.

(GPG has its own internal CCID driver, so `gpg --card-status` works even without
pcscd. That can mislead you into thinking smartcard access is fine.)

## `IdentitiesOnly` is load-bearing

`~/.ssh/config` pins every host to slot 9A:

```
Host *
    PKCS11Provider /usr/lib/libykcs11.so
    IdentityFile ~/.ssh/id_yubikey_piv.pub
    IdentitiesOnly yes
```

The token exposes **six** keys over PKCS#11 — slot 9A, four
`age-plugin-yubikey` retired slots, and the attestation key. Offering all six
hits the default `MaxAuthTries` of 6 on many servers, and the connection fails
before the right key is tried. `IdentityFile` + `IdentitiesOnly` restricts it to
9A alone.

**Adding another key later** (work deploy key, second GitHub account, a bastion)
requires its own `Host` block with an explicit `IdentityFile`. Do not relax the
global block — that reintroduces the `MaxAuthTries` failure.

## Checks that need no PIN

```bash
ykman info                                   # device, enabled applets
ykman piv info                               # slot contents
ssh-keygen -D /usr/lib/libykcs11.so          # keys OpenSSH can see
ykman fido info                              # FIDO2 PIN attempts remaining
curl -sS https://github.com/davidkhanks.keys # is the key registered?
```

Authenticating (`ssh -T git@github.com`) does need the PIV PIN.
